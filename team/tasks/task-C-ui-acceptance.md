## 1. 你的 Agent 必须遵守的规则

1. **`contracts/` 只读。** 你觉得事件契约缺事件，就走契约 PR 提，不要自己加订阅。
2. **只改 `web/src/ui/`、`web/src/demo/`、`docs/`。** 不要动机器人逻辑，也不要直接读机器人对象——**HUD 只订阅事件总线**。
3. **每个模块至少三条测试**（正常 / 边界 / 异常）。HUD 的测试重点：事件来了界面确实变了、没事件时不变、异常载荷不崩。
4. **不得为了跑通改测试预期。**
5. **不引入 UI 框架**（不装 React/Vue），纯 HTML + CSS。

## 2. 你要订阅的事件（唯一数据来源）

HUD **不得**直接读机器人对象或后端状态，只订阅这些：

| 事件 | 载荷 | 你用它做什么 |
| --- | --- | --- |
| `task:start` | `{taskId, query, source}` | 对话区加用户气泡、时间线开新行 |
| `task:say` | `{text, who}` | 对话区加气泡（`who` 决定左右） |
| `robot:state` | `{from, to, step, taskId}` | 状态条：当前状态 + 第几步 |
| `task:step` | `{taskId, index, action, target, ok, ms}` | 时间线里单步耗时 |
| `task:end` | `{taskId, ok, steps, durationMs, corrected}` | 时间线收尾、对比卡片数据 |
| `plan:received` | `{source, steps, latencyMs}` | **来源标签**（缓存/在线/规则/纠错/脚本） |
| `plan:rejected` | `{reason, raw}` | 状态条显示"降级中" |
| `plan:corrected` | `{objectId, to, source}` | 对话区加"已纠正"标记 |
| `memory:updated` / `:hit` / `:miss` | `{objectId, room, confidence, status}` | 记忆面板 |
| `robot:blocked` | `{reason, at}` | 状态条告警 |

## 3. 按步骤干活

### 步骤 2.3 HUD 骨架（3 h，你的主责）

四块界面，全部只订阅事件总线：

1. **对话区**：用户气泡 + 小方气泡；思考时三点动画。
2. **状态条**：当前状态、正在执行第几步、**来源标签**（缓存 / 在线 / 规则 / 纠错 / 脚本）。
3. **记忆面板**：每条显示物体名、分区、置信度条、更新时间；有变化时**高亮一秒**。
4. **任务时间线**：每次任务一行，展开显示各步骤耗时。

**设计规范**：
- 浅底卡片 + 单一品牌色；所有文案口语化、第一人称（管家口吻）。
- 置信度条三段色：**> 0.7 绿 / 0.3–0.7 黄 / < 0.3 灰**。
- HUD 统一贴左右两侧，**宽度不超过屏幕 22%**；1366×768 与 1920×1080 都不遮挡主画面。

**验收**：执行任一动作序列，四块界面同步刷新且无报错；两种分辨率不遮挡。

> 风险：界面挡三维画面。22% 是硬上限，别为了"更好看"放宽。

### 步骤 2.4 主持 M1 验收（0.5 h，硬节点 12:00）

1. 按 `docs/test-cases.md` 十条用例逐条过，记结果。
2. **M1 判定：十条通过 ≥ 8 条**，其余两条有明确修复计划。
3. 断后端跑五个离线脚本，全部跑通。

过不了时**立即启动降级**（这是你的提议权）：砍阶段 4 与阶段 5 全部可选项，下午只做 3.1 与 3.3。

### 步骤 3.4 时间线、来源标签、录屏（1 h）

1. **来源标签必须在纠错时显示"规则"**——这是给评委看的证据：这句话没走模型。
2. 时间线读任务日志表（后端已有 `corrected` 字段）。
3. **M2 后立即录屏**（1080p、含字幕），上传网盘 + 本地两处备份。**未录屏不得进入阶段 4。**

### 步骤 4.2 对比卡片（1 h）

1. 一键对比：关闭记忆 vs 开启记忆，两组真实日志（步骤数 / 行走距离 / 耗时）。
2. 两根对比柱（Chart.js），**数据全部读日志，不手写**。
3. 可点开查看原始步骤。

**验收**：一键对比 40 秒内完成并出图。

### 步骤 4.3 语音（1 h）

1. 语音合成：浏览器内置接口，中文女声，语速 1.1；台词与关键事件（找到了 / 我记住了 / 抱歉）播报。
2. 语音识别：按住说话、松开发送；识别失败提示改用文字。
3. **语音只作加分**，主演示以文字输入为准（现场嘈杂）。

### 步骤 6.1 主讲与彩排（2.5 h）

- 彩排三遍：**第一遍找问题、第二遍计时、第三遍断网**。
- 路演稿结构：痛点 → 演示 → 技术亮点 → 数据 → 愿景；**时长误差 ≤ 15 秒**。
- 兼计时。10:00 后一律不改代码，问题用导演模式绕开。

## 4. 你的验收用例（已在仓库 `docs/test-cases.md`，你是主笔）

十条主用例 + 八条纠正专项，每条四栏：**前置 / 操作 / 期望画面 / 期望日志**。

| # | 场景 | 关键期望 |
| --- | --- | --- |
| 1 | 首次找物 | 扫三房间，steps ≥ 5 |
| 2 | 记忆直达 | steps ≤ 4，confidence 0.90 |
| 3 | 物体被移动 | 旧条 0.85→0.45 标 stale，新条 0.80 |
| 4 | 取放 | 水杯落在茶几包围盒内 |
| 5 | **用户纠正（核心）** | 道歉 → 拿起 → 书房放下；source=corrective |
| 6 | 切换布局 | 记忆按布局隔离，切回完整保留 |
| 7 | 训练前后对比 | 数据来自真实日志 |
| 8 | 连点防抖 | 只执行第一条，提示"小方正在忙" |
| 9 | **断网降级** | 五句台词全过，来源显示"缓存" |
| 10 | 非法规划拦截 | 机器人不动，气泡"我没听懂"，随后降级 |

纠正专项 C1–C8 见 `docs/test-cases.md` 第二节（含"沙发上放不了东西""你说的是哪件东西"这类澄清话术）。

**你的活儿**：验收时逐条打勾，**问题写清"谁修、复测结果"**。

| 坑 | 怎么防 |
