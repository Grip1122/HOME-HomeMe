## 1. 你的 Agent 必须遵守的规则

1. **`contracts/` 只读。** `layout.schema.json` 和 `layout.example.json` 是别人（把关人）的产物，**你不能直接改**。你产出的是 `web/public/layouts/*.json` 实例。
2. **只改 `web/src/scene/` 与 `web/public/`。**
3. **每个模块至少三条测试**（正常 / 边界 / 异常）。场景加载器的测试重点是"坐标算得对"。
4. **大文件不入库**：`assets/gaussian-splat/` 下的 `.ply/.splat/.ksplat` 与 `web/public/models/` 下的 `.glb` 都被 `.gitignore` 排除。素材在 Release `splat-v1`，仓库只留**清单与校验和**。
5. **点云只管看，不管算**：寻路与抓取判定只读 layout 的 `size/blocks/surface`，**不读点云**；不许因为点云里家具位置不同就绕过 layout。

**判定"做完了"的硬标准**：`python scripts/check_layout.py` 对你的布局**零错误**，且你能证明它**会报错**（改坏一处，看它报什么）。

## 2. 你的数据格式（唯一真值，必须逐条满足）

### 2.1 必填字段

| 层级 | 必填 |
| --- | --- |
| 顶层 | `layout_id`、`grid`、`rooms`、`furniture`、`objects`（`doors`、`stains` 可选但本演示需要） |
| rooms | `id`、`name`、`rect`、`scan_point`、`drop_to` |
| doors | `id`、`between`、`pos`、`width`、`axis` |
| furniture | `id`、`name`、`room`、`pos`、`size`、`blocks`、`surface` |
| objects | `id`、`name`、`aliases`、`room`、`pos`、`on` |
| stains | `id`、`room`、`pos` |

### 2.2 六条建模要点

1. **单位统一为米，y 轴向上**，网格只管 x-z 平面。家具 `pos` 是**包围盒底面前左角**，`size` 是宽、高、深。
2. **`blocks` 决定是否占寻路格，`surface` 决定能否放东西。** 放置只允许落在 `surface=true` 的家具上。
3. **门洞决定跨房间可达**：`doors[]` 声明哪两个分区之间有洞、洞心位置与宽度。跨分区的相邻格**只有落在门洞范围内才连通**，否则视为墙。**宽度下限 1.0 米**（外扩 0.25 米后仍留 0.5 米净宽）。
4. **分区默认落点 `drop_to`**：让"把书放到书房"这种只说分区的指令有确定答案，不让模型猜。
5. **别名表**：物体与地点都带 `aliases`，规则解析与提示词共用。**别名在全局必须唯一**，否则"放到 X"会有歧义。
6. **每个分区一个扫描点**：落在本分区、不压阻挡格、且与其他扫描点互通。

### 2.3 现成的参照

`contracts/layout.example.json`：3 个分区（living / bedroom / study）、2 个门洞、10 件家具、8 个任务物体、2 处污渍。**你的 `layout_A.json` 就从它复制改**，不要从零写。

8 个任务物体（`cup_red` `bottle_green` `remote_black` `keys_yellow` `phone_white` `notebook_orange` `book_blue` `glasses_black`）分别放在 `table_dining` / `table_coffee` / `side_table` / `nightstand` / `bed` / `desk` 上。

## 3. 校验脚本会抓你什么（八类，全部零容忍）

```bash
python scripts/check_layout.py web/public/layouts/layout_A.json
```

| # | 检查 | 典型错法 |
| --- | --- | --- |
| 1 | 分区在网格内、互不重叠 | rect 写超了 `grid.cols/rows` |
| 2 | 别名重名 | 两个物体都有 `"杯子"` |
| 3 | 家具在其所属分区范围内 | 家具 room 写 A，坐标落在 B |
| 4 | 阻挡家具不重叠 | 两张 `blocks=true` 的桌子叠在一起 |
| 5 | **门洞宽度 ≥ 1.0 米** | 为了好看把门做成 0.8 米 |
| 6 | 扫描点在本分区、不在阻挡格、**可达** | 扫描点被沙发压住 |
| 7 | 物体在其家具台面范围内、高度贴合 | y 写成 0.5 但台面是 0.75 |
| 8 | **物体够得着**：最近可站格距 ≤ 1.0 米 | 笔记本塞进床和墙的 0.2 米夹缝 |

> 第 8 条是新的：抓取判定只看**水平距离 < 1 米**。示例布局实测 0.60–0.93 米，都在阈值内。你摆东西时**必须留出机器人站得下的位置**。

**这一步的验收不是"零错误"，而是"能报错"**：故意把某个门洞改成 0.8 米、把某件物体塞进夹缝，确认脚本报出对应类别，再改回来。这是审核时要看的证据。

## 4. 按步骤干活

### 步骤 0.1 取素材与选渲染器（1 h）

1. 从 Release `splat-v1` 下载 `scene.ply`，**先核对 sha256**（`901cf8ce…2678fae`，全文见 `assets/gaussian-splat/manifest.json`）。放进 `assets/gaussian-splat/`，**不入库**（已被 `.gitignore` 排除）。
2. 取 **RobotExpressive**（three.js 示例自带）。**不再需要家具模型包**：真实家具已经在点云里。
3. 用现成 viewer 打开 `scene.ply`，截图三张（总览、俯视、室内近景）。
4. 做三项验证（见 `assets/gaussian-splat/README.md` 第 5 节：浏览器能否打开 / 正交相机排序 / 帧率），结论写回该 README，并填 `manifest.json` 的 `renderer_decision`。**这一步没完成之前，不要写 layout 坐标。**

### 步骤 1.1 场景加载器：高斯泼溅 + 隐形碰撞层（3 h，关键路径，你的主责）

1. **点云层**：加载 `scene.ply` 的转换产物（`.splat` / `.ksplat`）。求出 `sceneScale`、`sceneOffset`、`upAxis`，三个常量**只在 `core/config.js` 定义一处**（该文件归设计 A，你把数值交给 Jesu 写入，不要自己改）。
2. **标定方法**：在点云里找一个已知尺寸（门高约 2.0 米、桌高约 0.75 米），量出点云坐标下的长度，算缩放系数；再确认 y 轴朝上。**标定数值必须人工实测，不能让 AI 猜。**
3. **碰撞层**：按 layout 的 `blocks` 家具生成**不可见**包围盒（`material.visible = false`，保留在场景图里），供寻路与射线检测使用。**不要再放 GLB 家具**，否则出现"两套家具"错位。
4. **台面层**：`surface=true` 的家具生成不可见台面平面，物体落点取该平面高度。
5. **语义层**：门洞按 `doors[]` 生成不可见通行区。
6. **物体**：8 件任务物体用彩色小几何体（水杯红色圆柱、钥匙黄色方块），**必须明显区别于点云背景**。
7. 注册表三个查询：按 id 取对象 / 按分区列出物体 / 取世界坐标。

**关键**：物体挂载一律 `attach()`（保持世界变换），禁止 `add()`。测试：挂载前后世界坐标差 < 1e-6。

**验收**：打开页面看到点云画面；网格辅助线与点云里的真实家具肉眼对齐；控制台调注册表能取到指定物体。

> 风险：①缩放或朝上轴判断错（用已知尺寸校验）；②正交相机下高斯排序出错——若出现，立刻告知 Jesu 和 wei，**固定视角方案要重设计**；③200 万点掉帧——预案是抽稀。

### 步骤 2.1 携带锚点调校（1 h，配合设计 A）

设计 A 写抓取动画，你负责**锚点位置**是否自然：
1. 在 `core/config.js` 的锚点配置下试不同偏移，找出"物体看起来在手里"的位置。
2. **逐帧检查抓取录屏**：手有没有进家具、物体有没有穿桌面。
3. 报告 0.4 倍缩放的实际观感（建议同时试 0.5 倍给把关人对比）。

### 步骤 4.1 第二套布局（2 h，非关键路径）

同一户型轮廓，**家具全部重排、物体初始位置全部改变**。要求：
- 复用同样的分区轮廓与门洞位置（保证"同一 Agent 换环境"的对比干净）
- 所有家具朝向、位置重算，仍要过 `check_layout.py` 八项
- 物体全部换家具放置

**可选加分**（时间够才做）：随机布局生成器——拒绝采样，逐件家具在允许分区内随机取位置与四朝向之一；与已放家具重叠、或导致任一扫描点不可达（用 A\* 检查）就重抽，最多 200 次。**固定随机种子**保证可复现。

### 步骤 5.1 泼溅质量调优（4 h，非关键路径，可从白天起并行）

1. **抽稀与分块**：按视野分块加载；必要时 200 万点抽到 50–80 万，抽稀前后对比，肉眼无差别才合格。
2. **曝光与色调**：统一亮度与白平衡，使彩色任务物体一眼可辨。
3. **裁掉离群点**：外围稀疏高斯只保留主体区域。
4. **性能**：首屏 < 8 MB、普通笔记本 50 帧以上。

**铁律**：所有变换只改点云，不改 layout 坐标；点云若被平移或缩放，必须同步通知 Jesu 更新 `sceneScale/sceneOffset`。

**验收**：两套布局都在点云上正确显示；帧率达标；截图三张用于路演封面。

### 步骤 5.2 污渍（0.5 h）

在 `stains[]` 里定位置（客厅、卧室各一处），做贴图。相机点报告条目要能平滑飞到对应污渍——**飞行由设计 A 实现，你只提供坐标**。

## 7. 你最容易踩的坑

| 坑 | 怎么防 |
| --- | --- |
| 门洞被外扩吃掉 | 门洞 ≥1.0 米，跑脚本确认；改布局必重跑 |
| 物体够不着 | 每摆一件新物体就跑 `check_layout.py` |
| 家具重叠 | 两张 `blocks=true` 的家具别贴太近（脚本会报） |
| 点云与隐形碰撞层错位 | 渲染网格辅助线 + 不可通行格红标，与点云里的真实家具肉眼比对 |
| 抽稀或裁剪后寻路崩 | 变换只改点云，不改 layout；点云被缩放必须同步 `sceneScale` |
| 切换布局掉帧 | 释放旧几何体/材质/贴图（与设计 A 配合） |
