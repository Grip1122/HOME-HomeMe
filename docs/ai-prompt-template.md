# 交给 AI 的任务说明模板

> 把 AI 当作「按契约交付的外包工程师」，不是聊天对象。每个模块开工前，负责人先填这张卡，再连同 `contracts/` 一起交给 AI。

---

## 模板

```text
【角色】你是资深 <three.js / FastAPI / 前端 UI> 工程师，只负责下面这一个模块。

【目标】实现 <文件路径>，导出 <函数签名>。

【契约】以下文件是唯一真值，只读：
  - contracts/<相关 schema>
  - contracts/layout.example.json
  - contracts/events.md
你不得修改 contracts/ 下的任何文件。若你认为契约有问题，停下来，只输出一段
「契约问题说明」（哪一行、为什么、建议怎么改），不要写绕过它的代码。

【约束】
  1. 只修改：<允许修改的文件清单>。其余文件一律不碰。
  2. 不得新增依赖；确需新增，先问我。
  3. 纯函数优先；有副作用的部分集中在一处并写明。
  4. 不得用空 catch 或默认值掩盖错误；失败要通过事件或返回值显式暴露。
  5. 不得为了让测试通过而放宽 Schema、删除断言或改测试预期。

【验收用例】（必须逐条对应一个测试）
  1. <正常路径>
  2. <边界：空 / 零 / 满 / 重复>
  3. <异常：非法输入 / 非法状态转移 / 超时>
  4. <异步：中途取消 / 并发两次调用>

【输出】
  A. 完整实现代码
  B. 测试文件（框架：Vitest / pytest），每个验收用例一个 test，名字写成句子
  C. 一段「我做了哪些假设」，列出所有你自己补的前提
```

## 示例 1：寻路网格（设计 A，步骤 1.3）

```text
【角色】你是资深 three.js 工程师，只负责寻路网格模块。
【目标】实现 web/src/nav/grid.js，导出 buildGrid(layout) 与 findPath(grid, from, to)。
【契约】layout 结构见 contracts/layout.schema.json；返回世界坐标数组 [[x,0,z], ...]。
【约束】只改 web/src/nav/ 下的文件；只用 pathfinding 包；纯函数，不访问三维场景；
        外扩半径 0.25 m，门洞 >= 1.0 m；不得修改 contracts/ 与其他模块。
【验收】
  1. 起终点相同返回单点；
  2. 被家具完全包围返回空数组，不抛异常；
  3. 客厅到书房路径不穿过任何 blocks 家具，且经过门洞；
  4. 同一输入调用两次结果一致（无隐藏状态）。
【输出】完整代码 + Vitest 测试 + 假设清单。
```

## 示例 2：抓取动作（设计 A，步骤 2.1）

```text
【角色】你是资深 three.js 工程师，只负责 actions/grab。
【目标】实现 web/src/robot/actions.js 的 grab(ctx, targetId)，返回 Promise。
【约束】
  - 逻辑与视觉解耦：距离 < 1.0 米（水平面）即判定可抓取，不做手部碰撞检测；
  - 物体挂载必须用 attach()（保持世界变换），禁止 add() 后手改 position；
  - 物体进入携带锚点后缩放为 0.4 倍；
  - 动画只用 Punch 片段做快速过渡，总时长 <= 0.5 s；
  - 不添加任何发光/描边/辉光效果；
  - 单飞锁必须在 finally 中释放。
【验收】
  1. 距离 0.9 米抓取成功，holding 等于 targetId；
  2. 距离 1.1 米抓取失败，返回 {ok:false, reason:"too_far"}，物体不移动；
  3. 挂载前后物体世界坐标差 < 1e-6（防瞬移）；
  4. 抓取中途再次调用 grab 被拒绝，不产生第二个挂载；
  5. 动画中途抛错，锁仍被释放，下一次调用可正常执行。
```

## 示例 3：纠错规则（AI-D，步骤 3.4）

```text
【角色】你是资深 Python 工程师，只负责 server/app/rules.py。
【目标】实现 try_correct(query, index, last_object, holding)。
【约束】纯正则 + 词典，不得调用任何网络或大模型；耗时 < 5 ms；
        地点词占用的字符在抽取物体前必须遮掉（“书房”里的“书”不是物体）；
        否定结构后的地点不得被当作新地点。
【验收】见 tests/test_rules_correction.py 现有 30 余条，只增不减。
```

## 审核人如何使用这张卡

收到 PR 时，先对照这张卡里的【约束】逐条检查：
- 约束 1（只改允许文件）→ 看 `git diff --stat`
- 约束 2（不加依赖）→ 看 `package.json` / `requirements.txt` 有无变化
- 约束 5（不改测试预期）→ 看测试文件 diff 里有没有「删除一行断言」

AI 偏离任务卡的地方，就是审核时最该看的地方。
