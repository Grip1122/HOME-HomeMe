# 十条可判定验收用例

> 设计 C · 对应步骤 0.2 / 2.4  
> 判定原则：每条都必须能回答“画面看到了什么、日志/数据变了什么、怎么算通过”，不写“看起来正常”。

## TC-01 首次找物（记忆关闭）

**前置条件**

- 打开应用，记忆为空或 `memory_enabled=false`。
- 机器人位于出生点，水杯在客厅茶几。

**操作**

1. 输入「帮我找红色水杯」。
2. 观察机器人依次扫描客厅、卧室、书房。
3. 等待找到。

**期望画面**

- 状态从「思考中」→「前往中」→「观察中」→「完成」。
- 时间线出现 3 次「扫描 X」+「前往」+「视觉复核」+「确认目标」。
- 记忆面板从 0 条增长到 8 条；扫描到水杯时条目高亮一次。
- 找到后目标卡片显示：红色水杯 / 客厅 / 茶几 / 置信度 ≥ 80%。

**期望日志 / 数据**

- `task_log.source = rule`（或离线脚本）。
- `step_count` 约 6（不含解析与最终确认时为 5）。
- 记忆表新增 8 条，水杯 `confidence = 0.80`，`source = observe`。
- 无 `error` 状态；无重复任务。

**通过标准**

- 画面与日志一致；步骤数可逐条展开；水杯记忆位置为客厅茶几。

## TC-02 记忆直达

**前置条件**

- 已完成一次全屋扫描，水杯记忆置信度 ≥ 0.80。
- `memory_enabled=true`。

**操作**

1. 输入「我的红色水杯在哪？」。

**期望画面**

- 规划来源显示「规则解析」或「缓存命中」。
- 时间线只有：检索记忆 → 前往客厅 → 视觉复核 → 确认目标（4 步）。
- 不出现「扫描卧室 / 书房」。
- 置信度条从 86% 动画到 91%。

**期望日志 / 数据**

- `task_log.step_count ≤ 4`。
- 水杯 `confidence` +0.05，上限 1.0。
- 未产生新的扫描记录。

**通过标准**

- 4 步内完成；记忆置信度增加；旧位置未被误报。

## TC-03 记忆开关对比

**前置条件**

- 同一布局、同一初始物体位置、同一指令。
- 机器人复位到同一出生点。

**操作**

1. 关闭记忆，执行「帮我找红色水杯」，记录步骤数、耗时、行走距离。
2. 重置场景，开启记忆，再执行同一句，记录同样三项。
3. 打开对比卡片。

**期望画面**

- 对比卡片双列：记忆开 / 记忆关。
- 两组数据都来自任务日志，不手填；可展开原始步骤。
- 记忆开：约 4 步 / 5–7s；记忆关：约 8 步 / 15–20s（以现场日志为准）。

**期望日志 / 数据**

- 两条 `task_log`，`memory_enabled` 分别为 0 / 1。
- 步骤数差值 ≥ 2；耗时差值 > 0。
- 不能出现“记忆关也用记忆直达”。

**通过标准**

- 数据可复现；差异可由步骤列表解释；没有伪造日志。

## TC-04 物品被移动（记忆过期）

**前置条件**

- 已完成扫描，水杯记忆在客厅茶几，置信度 0.86。
- 通过导演模式或拖拽把水杯移到卧室床头柜，记忆未更新。

**操作**

1. 输入「帮我找红色水杯」。

**期望画面**

- 机器人先到客厅旧位置。
- 地面出现红色虚线「记忆位置」标记。
- 复核步骤变红，状态点变红，文案「咦，这里没有…」。
- 水杯条目置信度降到约 45%，显示「待复核」。
- 随后扫描三区；卧室扫描后条目恢复绿色 80%，房间/家具更新为卧室 · 床头柜。
- 最终到卧室找到，目标卡片出现。

**期望日志 / 数据**

- 旧条目 `confidence` 约 0.45，`status = stale`。
- 复扫后 `confidence = 0.80`，位置覆盖为卧室床头柜。
- 步骤数明显多于记忆直达（约 9–12）。
- 无“直接命中旧位置”的假成功。

**通过标准**

- 旧位置失败 → 复扫 → 新位置成功；记忆与画面一致。

## TC-05 用户纠正

**前置条件**

- 记忆里水杯在客厅（或任意错误位置）。
- 用户知道水杯实际在书房书桌。

**操作**

1. 输入「不对，水杯应该在书房」。

**期望画面**

- 小方先表达歉意，再确认新位置。
- 记忆面板旧条目先降置信度，再新增/更新为书房 · 书桌，置信度 90%。
- 时间线出现「记忆纠正」步骤，状态为完成。
- 机器人前往书房并复核成功。

**期望日志 / 数据**

- 旧位置 `confidence -0.30`；新位置 `confidence = 0.90`。
- `task_log.corrected = 1`。
- 不出现“反复去旧位置”的循环。

**通过标准**

- 纠正被持久化；下一次同一指令直接去书房。

## TC-06 切换布局

**前置条件**

- 布局 A 有 8 条记忆；布局 B 尚未扫描或已有独立记忆。
- 导演模式可用。

**操作**

1. 切到布局 B。
2. 输入「帮我找红色水杯」。
3. 切回布局 A，再查一次。

**期望画面**

- 布局标签变为「布局 B」。
- 记忆面板只显示 B 的条目；A 的条目不出现在 B。
- B 中水杯位置与 B 场景一致（书房书桌）。
- 切回 A 后，A 的 8 条记忆完整保留。

**期望日志 / 数据**

- 记忆按 `layout_id` 分区，互不覆盖。
- 布局切换不产生重复 `object_id`。
- 同一句指令在 B 仍可完成。

**通过标准**

- 两个布局记忆互不污染；同一 Agent 在新布局可工作。

## TC-07 断网 / 规划降级

**前置条件**

- 已建立记忆；后端在线规划可用。
- 导演模式「断网模拟」可用。

**操作**

1. 开启断网模拟。
2. 输入「帮我找红色水杯」。
3. 观察规划来源标签。

**期望画面**

- 顶部出现 OFFLINE 徽标。
- 规划来源切到「规则解析」或「离线脚本」。
- 机器人仍完成找物；对话说明已切换。
- 不出现无限 loading。

**期望日志 / 数据**

- `source` 为 `rule` / `cache` / `offline`，不是 `llm`。
- 请求不因网络失败而中断任务；降级事件被记录。
- 任务有明确结束状态。

**通过标准**

- 断网也能完成一次完整找物；降级可见、可解释。

## TC-08 单飞锁

**前置条件**

- 应用空闲。

**操作**

1. 快速连续点击发送 / 快捷指令 10 次。
2. 在动画执行中再次点击。

**期望画面**

- 第一次任务正常开始；其余点击被忽略或提示“正在执行”。
- 机器人不抖动、不重叠、不出现两个目标高亮。
- 输入框在任务期间禁用，结束后恢复。

**期望日志 / 数据**

- 只有一条 `task:start` 到 `task:end`。
- 无“任务未结束又开新任务”。
- 队列长度不超过 1。

**通过标准**

- 连点 10 次不产生状态错乱；任务日志只有一条。

## TC-09 分辨率与遮挡

**前置条件**

- 1366×768 与 1920×1080 两种窗口。
- 浏览器缩放 100%。

**操作**

1. 分别打开应用。
2. 触发记忆直达与目标卡片。
3. 打开导演面板与对比卡片。

**期望画面**

- 左右面板不遮挡机器人 / 目标物。
- 底部对话区不遮住机器人的下半身。
- 目标卡片在对话区上方，不与输入框重叠。
- 页面无横向/纵向滚动条。
- 导演抽屉打开后不遮住关闭按钮。

**期望数据**

- 布局测量：`bodyScroll == viewport`。
- 左右面板与底部对话区无交叠。
- 目标卡片与对话区无交叠。

**通过标准**

- 两种分辨率均无遮挡；投屏后文字可读。

## TC-10 HUD 同步与高亮

**前置条件**

- 应用空闲；记忆有 8 条。

**操作**

1. 执行一次记忆直达。
2. 执行一次物品移动后的复扫。
3. 执行一次用户纠正。

**期望画面**

- 状态条、时间线、记忆面板、目标卡片在同一任务内同步更新。
- 记忆变化条目高亮 1 秒，不全部闪烁。
- 时间线当前步骤有脉冲点；完成步骤变绿；错误步骤变红。
- 规划来源标签在任务开始时更新，不滞后到下一条。
- 目标卡片出现 / 收起不遮挡输入框。

**期望日志 / 数据**

- `memory:update` 与 `task:step` 的顺序正确：
  - 复核失败 → 置信度下降 → 复扫 → 记忆更新 → 找到。
- 不出现“面板先显示新位置、日志仍是旧位置”。
- 不出现“时间线没有步骤、状态却完成”。

**通过标准**

- 四块区域数据一致；刷新页面后记忆仍可恢复。

## 附：判定证据留存

每条用例执行时至少留存：

1. 屏幕录制或 3 张关键帧（开始 / 中间 / 完成）；
2. 浏览器控制台 `window.__demo.getState()` 输出（若已有）；
3. 任务日志一行（步骤、耗时、来源、是否纠正）；
4. 记忆表变化前后的截图或 SQL 查询结果。

> 现场答辩时，评委追问“这几步是真的吗”，直接展开时间线与任务日志即可。
