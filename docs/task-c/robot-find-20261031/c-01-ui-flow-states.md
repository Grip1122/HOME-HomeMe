> 母版：`robot-find`（实景找物演示）。本文档描述的每个状态都对应母版里已实现、可在浏览器中复现的代码路径，行号指向 `src/scene-find.js` 与 `src/realtwin.js`。

## 1. 产品定位与一句话流程

用户用自然语言说出要找的物品 → 机器人查本机空间记忆 → 规划路径并前往 → 到位后验证 → 命中则镜头推进并弹出结果卡；未命中则就地重新扫描、更新记忆、再次前往。

全链路离线：空间模型、物品记忆、检索评分都在本机，记忆写入浏览器 `localStorage`（键 `rf.sdcard.pack.SCENE` / `rf.sdcard.meta.SCENE`），对应演示话术中的「机身 SD 卡」。

## 2. 屏幕结构（三层）

| 层 | 内容 | 实现位置 |
| --- | --- | --- |
| L1 底层 · 3DGS 实景 | `scene.splat` 高斯点云 + 加入 `threeScene` 的 Three.js 机器人模型 | `src/realtwin.js`、`scene-find.js:1106` |
| L2 投影层 · 世界锚点标记 | 物品记忆点、机器人铭牌，由相机投影到 DOM | `scene-find.js:1163`（`_projectMarkers`） |
| L3 操作层 · 面板与控件 | 检索输入、建议词、记忆列表、任务时间线、进度条、结果卡、地平线微调 | `index.html` + `src/realtwin.css` |

L3 是固定布局面板，不随相机变化；L2 必须每帧跟随相机重算。两者不可互相替代。

## 3. 主流程状态机

```
                   ┌─────────────────────────────────────────┐
                   │                                         │
  [closed] ──open──▶ [loading] ──ok──▶ [ready/idle] ◀────────┘
                   │                      │
                   └──fail──▶ [error]     │ 全屋扫描
                                │         ▼
                             retry   [scanning] ──done──▶ [memory-ready]
                                                               │
                                              用户检索 query   │
                                                               ▼
                                                          [planning]
                                                               │
                                     ┌── 无匹配 ──▶ [no-match] ┤
                                     │                         ▼
                                     │                   [navigating]
                                     │                         │
                                     │                         ▼
                                     │                    [verifying]
                                     │                    │        │
                                     │              命中  │        │ 未命中（记忆过期）
                                     │                    ▼        ▼
                                     └──────────────  [found]   [stale-detected]
                                                                   │
                                                                   ▼
                                                              [rescanning]
                                                                   │
                                                                   ▼
                                                          [navigating] → [found]
```

### 3.1 状态定义表

| 状态 | 触发 | 画面表现 | 禁止表现 |
| --- | --- | --- | --- |
| `closed` | 初始 / 按 Esc / 点关闭 | 实景层隐藏，渲染循环停止（`stopViewer`） | 后台继续渲染耗电 |
| `loading` | 首次 `open()` | 遮罩 + 进度条 + 副标题「读取 47.5 MB 压缩高斯点」→「解码中 · {label}」；状态胶囊「加载中」 | 进度条停在 0 却无文案 |
| `error` | 缺渲染库 / `file://` 协议 / 解码异常 | 错误遮罩 + 具体原因 + 「重试」「关闭」 | 只显示「未知错误」而不给出可执行建议 |
| `ready/idle` | 加载完成 | 状态胶囊「已就绪 · {秒}s」+ splat 计数「1,555,624 splats」；镜头回到总览位 | 就绪后仍显示加载遮罩 |
| `scanning` | 点「全屋扫描」 | 扫描进度条按 `pct` 推进，记忆点逐个点亮 | 一次性全部点亮（失去扫描感） |
| `memory-ready` | 扫描完成 | 播报「扫描完成。我记住了 N 件物品的位置，数据只写在本机 SD 卡。」记忆列表 8 条，均为 `fresh` | 把条数写死为 8，应取 `revealed.size` |
| `planning` | 提交检索词 | 播报规划话术，任务时间线出现首步 | 跳过规划直接移动 |
| `no-match` | 检索词无命中 | 提示未匹配 + 保留建议词，不进入执行态 | 任意挑一个物品假装命中 |
| `navigating` | 规划完成 | 机器人沿 `过道 → 目标列 → 停靠点` 三段路径移动并转向；任务进度条推进 | 直线穿越家具 |
| `verifying` | 抵达停靠点 | 镜头对准目标位 | 未到位就判定结果 |
| `found` | 验证命中 | `_focus(rec.src, 950)` 镜头推进 + 结果卡 +「找到啦！{名称}在{区域}的{家具}。」+ 置信度百分比 | 置信度写死 100% |
| `stale-detected` | 旧位置验证失败 | 播报「咦，{名称}不在这里，物品可能被移动了。我重新扫一遍。」该记忆标记 `stale`，标记点隐藏 | 静默失败 |
| `rescanning` | 自动触发 | 二次扫描，命中后 `status` 回写 `fresh` | 需要用户手动再点一次 |

### 3.2 记忆条目状态

两态，定义在 `scene-find.js`：

- `fresh`：位置可信，标记点可见，可直接导航。
- `stale`：位置已失效（物品被移动）。标记点隐藏（`scene-find.js:1173`），下次检索时先去旧位置、失败后自动重扫。

状态迁移：`fresh --demo:teleport/物品被移动--> stale --重扫命中--> fresh`

## 4. 失败与空数据设计（必须保留）

| 场景 | 设计要求 |
| --- | --- |
| `file://` 直接打开 | 明确告知浏览器安全策略禁止读取 47.5 MB 模型，并给出「双击 start.bat → 访问 http://127.0.0.1:8765/index.html」的具体步骤 |
| 渲染库缺失 | 指出缺失文件路径 `assets/gaussian-splats-3d.umd.js` |
| WebGL 上下文耗尽 | 提示「关闭该标签页重新打开」 |
| 记忆包版本不符 | `SCENE_ID` 不匹配或 `matched` 计数为 0 时丢弃旧包，回到未扫描态，不加载半套脏数据 |
| 检索无结果 | 停在 `no-match`，不编造目标 |
| 任务失败 | 进度条不得补到 100% |

最后一条是硬约束：**任何失败态都不允许把进度显示为 100%。**

## 5. 相机与视角设计

| 预设 | 位置 | 朝向 | 用途 |
| --- | --- | --- | --- |
| `overview` | `[-3.8, 1.6, 0]` | `[3.8, 1.6, 0]` | 默认总览，沿 +X 轴看向房间纵深 |
| `interior` | `[2.8, 1.7, 1.2]` | `[-2.0, 1.2, 0.0]` | 室内反打 |

- 视场角 42°，近远裁剪 `0.1 / 140`。
- 聚焦镜头 `_focus`：x 取 `clamp(p.x * 0.45, -2.0, 2.0)`，z 取 `clamp(p.z + 1.5, -1.4, 1.6)`，防止镜头穿墙。
- 镜头补间结束必须同步 `controls.target` 并关闭阻尼后 `update()`，否则 OrbitControls 会把相机拉回原位（已修复，见 `scene-find.js` 补间收尾）。
- 地平线微调：界面提供 `↺ / {角度}° / ↻` 按钮组，绕视线轴施加 roll，用于不同显示设备上的水平校正，默认 `0°`。

## 6. 文案与播报规范

- 第一人称、短句，不用感叹号堆叠。
- 报结果必须同时给出「区域 + 家具 + 置信度」，例：`找到啦！黑色大长方体物体在C 区 · 右侧的层板。`
- 失败播报要说明下一步动作，不只说失败。
- 隐私话术统一为「数据只写在本机 SD 卡」。
