# 把关人审核清单

> 用法：每份 PR 按顺序过三关。**任何一关出现「一票否决」项，直接打回，不看后面的代码。**
> 平均目标：小 PR 3 分钟，大 PR 10 分钟。超时就说明 PR 切得太大，要求拆分。

---

## 第 0 关：契约（30 秒，机器判）

```bash
gh pr diff <PR号> --name-only | grep '^contracts/' && echo "改动了契约" || echo "干净"
```

| 检查 | 一票否决 |
|---|---|
| PR 是否改了 `contracts/` | 改了、但标题不是 `[CONTRACT]`、或同时含业务代码 → **打回** |
| 若确为 contract PR：`contracts.lock.json` 是否同步 | 没同步 → **打回**（说明是手改示例没刷指纹） |
| 若确为 contract PR：`CHANGELOG.md` 是否有一行 | 没有 → **打回** |
| 是否删除或重命名了既有字段 | 是 → **打回**（只增不删，见 `contracts/README.md`） |

> 这一关可以直接看 CI 的 `contract-gate` job，绿了就不用自己再跑。

## 第 1 关：测试有效性（90 秒，最容易被糊弄的一关）

| 检查 | 一票否决 |
|---|---|
| PR 是否含测试文件改动 | 改了逻辑却零测试 → **打回** |
| 是否贴了「故意改错 → 测试变红」的证据 | 没有 → **打回**。不接受“我本地跑过了” |
| 证据里的失败测试，是否就是本 PR 新增/修改的那条 | 失败的是别的老测试 → **打回**（说明新测试根本没覆盖新代码） |
| 边界覆盖：空值 / 零 / 满 / 重复 / 非法顺序，至少各一条 | 只有 happy path → **打回** |
| 异步代码是否断言了「等待条件」而不是固定 sleep | 用 `sleep(1000)` 断言 → **打回**（演示机负载一高就假红） |
| 测试是否捕获了异常却断言为通过（`try/except: pass`） | 有 → **打回** |

**快速验证命令**（不信 PR 里的截图，自己跑一遍变异）：

```bash
gh pr checkout <PR号>
python -m pytest -q            # 必须全绿
python scripts/mutation_demo.py -k <本PR相关的变异名>
```

## 第 2 关：代码与边界（2 分钟）

### 2.1 接口与边界

| 检查 | 一票否决 |
|---|---|
| 是否只改了自己 `CODEOWNERS` 归属的目录 | 越界改别人模块 → **打回** |
| 是否 `from scripts.` 反向依赖运维脚本 | 有 → **打回** |
| 新增依赖 | 未经同意引入 → **打回**；同意了的要在 PR 里写明理由与体积 |
| 是否硬编码了绝对路径 / 端口 / 密钥 | 有 → **打回**（密钥泄露立即作废并轮换） |
| 是否硬编码了演示数据（把某句话的结果写死在逻辑里） | 演示台词只能进 `cache.json`，写进代码 → **打回** |

### 2.2 AI 生成代码的典型坑（重点看这几处）

| 坑 | 怎么看出来 | 处理 |
|---|---|---|
| **异步竞态**：`await` 前读了状态、`await` 后直接用 | 搜 `await` 前后同一个变量 | 要求改成「await 后重新读」或加版本号校验 |
| **状态机死锁**：某状态没有任何出边，或出边条件互斥 | 对照 `contracts/events.md` 的状态表逐条走 | 必须有「非法转移抛错」测试 |
| **静默兜底**：`catch {}` / `except: pass` / `?? 默认值` 掩盖了真错误 | 搜空 catch 与裸 except | 至少要 `console.warn` + 事件上报 |
| **擅自改 Schema**：为了让代码跑通，把 `required` 去掉、把枚举加宽 | 看 contract diff | 一票否决，按契约流程重来 |
| **假单飞锁**：`if (busy) return;` 但没有在 `finally` 里释放 | 看有没有 `finally` / `.finally()` | 必须有「连点 10 次不重叠」的测试 |
| **边界嗅探**：`array[0]` 不判空、`parseInt` 不判 NaN | 搜裸索引与 `parse` | 要求补测试用例 |

### 2.3 演示可用性

| 检查 | 一票否决 |
|---|---|
| 失败时是否有可见反馈（气泡/日志/状态），而不是静默卡住 | 卡死无提示 → **打回** |
| 新增逻辑是否会拖慢首屏或单帧（>16 ms） | 主线程里做重计算 → **打回** |
| 断网时该路径是否仍可走（cache / rule / script 三档） | 只有联网才通 → **打回** |

## 第 3 关：合并动作（30 秒）

- [ ] 用 **Squash and merge**，标题符合 `type(scope): 摘要` 且带步骤号
- [ ] 合并后删除远端分支
- [ ] 若对应里程碑，由**把关人**打 tag（作者不得自己打）
- [ ] 若本 PR 改变了别人正在用的行为，在群里点名同步

## 打回话术模板

打回时写清「哪一关、哪一条、怎么改」，不要只说“再看看”：

```text
打回，第 1 关：测试无效。
- 你新增的 test_grab_scope 只断言了 resolve，没断言物体最终世界坐标；
- 把 `holding == obj` 改成 `if True` 后该测试仍然通过（我本地复现了）；
- 需要补：抓取后物体世界位置在携带锚点 ±0.05 m 内，且能捕获“改坏就红”。
```

---

## 一票否决清单（背下来）

1. 改契约混进业务代码。
2. 没有能失败的测试，或变红证据是假的。
3. 越界改别人模块且未打招呼。
4. 硬编码密钥 / 绝对路径 / 演示台词。
5. 擅自放宽 Schema 让代码通过。
6. 空 catch 掩盖错误且无日志。
7. 状态机存在无法退出的状态。
