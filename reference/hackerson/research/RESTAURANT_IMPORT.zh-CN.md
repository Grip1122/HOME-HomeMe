# 餐厅场景适配检查

**后续状态：已完成试用接入，运行服务默认使用餐厅。以下为接入前的检查记录；当前实现与验证见 [餐厅接入记录](../RESTAURANT.zh-CN.md)。**

输入：`天安骏业集团餐厅.zip`，压缩约 225 MiB。已将指定的两个文件解压到 `assets/restaurant/`，保留原始压缩包。

## 确认结果

- `scene.ply`：binary little-endian，999,131 个顶点记录，含坐标、旋转、尺度、不透明度及球谐颜色系数；没有 face 元素。
- 这是 3D Gaussian Splatting 资产，不是可直接导入 MuJoCo 的三角网格，也不能仅把高斯中心当成坚实表面。
- `license.txt` 随包声明作者 Hilo、来源 https://superspl.at/scene/40c67340、CC BY 4.0，要求署名。原文已保留。
- 已解析属性、坐标和不透明度统计，见 `restaurant_asset.json`。尚未确认上方向、米制尺度、地面高度、可行走区域与扫描完整性。
- 大范围坐标尾部需要进一步检查，不能直接把全体高斯的包围盒当成实际餐厅尺寸。

## 推荐接入方式

1. 用支持 3DGS 的渲染器呈现餐厅原始外观，先确认方向、裁剪范围和尺度。
2. 从高斯场景生成体素或简化三角网格，人工检查地面、桌椅、墙和门洞，作为碰撞/导航代理。
3. 将原场景、代理几何、机器人和相机统一到同一个坐标系；已知长度用于米制标定。
4. 移动与碰撞使用代理几何。相机画面使用 3DGS；深度可来自代理网格，或由支持深度输出的高斯渲染器生成。二者应标明来源，不能默认高斯期望深度等于物理表面距离。
5. 重新构建扫描候选、导航地图和覆盖率参考，不沿用演示房间的箱体真值与 99.8% 指标。
6. 对原扫描缺失区域单独标记，避免把已有资产从未记录的表面当作机器人可以补采的真实信息。

## 可用开源工具

- [PlayCanvas splat-transform](https://github.com/playcanvas/splat-transform)：高斯格式处理、裁剪与碰撞代理生成。官方提供 `--collision-mesh` 路线；参数依赖实际场景尺度与内部种子位置，当前不能盲用默认坐标。
- [官方高斯场景物理接入示例](https://blog.playcanvas.com/turning-a-gaussian-splat-into-a-videogame/)：视觉场景配独立碰撞网格与导航网格。
- [gsplat 渲染接口](https://docs.gsplat.studio/main/apis/rasterization.html)：提供 RGB 与深度输出，可作为服务器端相机渲染候选；当前使用的 Python 环境未安装 PyTorch/gsplat，尚未编译验证。
